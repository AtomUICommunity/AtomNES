# PPU：Ricoh 2C02

> 对应源码：`AtomNES.Device/Ppu/Ppu2C02.cs`、`AtomNES.Device/Display/`。

## 1. 概览

| 项目 | NTSC 值 |
|------|---------|
| PPU 时钟 | 主时钟 ÷ 4 ≈ 5.369 MHz（CPU 的 3 倍） |
| 每行点数 | 341 |
| 每帧行数 | 262（可见 0-239，后渲染 240，VBlank 241-260，预渲染 261） |
| 输出分辨率 | 256 × 240 |
| 颜色 | 64 色主调色板（实际可用 54 种左右），屏幕上同时 25 色 |

PPU 有自己的 14 位地址空间，和 CPU 只通过 `$2000-$2007` 八个寄存器通信。

## 2. PPU 地址空间

```text
$0000-$0FFF  图案表 0（卡带 CHR ROM/RAM）
$1000-$1FFF  图案表 1
$2000-$2FFF  4 个名称表（实际只有 2KB CIRAM，由卡带决定镜像方式）
$3000-$3EFF  $2000-$2EFF 的镜像
$3F00-$3F1F  调色板 RAM（$3F10/$14/$18/$1C 是 $3F00/$04/$08/$0C 的镜像）
```

- **图案（tile）**：8×8 像素，每像素 2 位，占 16 字节（两个位平面）。
- **名称表**：32×30 个 tile 编号 + 64 字节属性表（每 16×16 像素区域选一个 2 位调色板）。
- **镜像**：水平、垂直、单屏、四屏，由卡带的 CIRAM A10 接线或 Mapper 控制。

## 3. CPU 寄存器

| 地址 | 名称 | 说明 |
|------|------|------|
| `$2000` | PPUCTRL | NMI 使能、精灵尺寸、背景/精灵图案表、地址增量、基础名称表 |
| `$2001` | PPUMASK | 显示开关、左 8 像素裁剪、灰度、颜色强调 |
| `$2002` | PPUSTATUS | VBlank、精灵 0 命中、精灵溢出；读取会清除 VBlank 和写锁存 w |
| `$2003/$2004` | OAMADDR/OAMDATA | 精灵属性内存（256 字节） |
| `$2005` | PPUSCROLL | 两次写：X、Y 滚动 |
| `$2006` | PPUADDR | 两次写：VRAM 地址高、低字节 |
| `$2007` | PPUDATA | VRAM 读写，读取有一级缓冲（调色板除外） |

### 内部寄存器 v / t / x / w（Loopy 模型）

```text
v, t: 0yyy NNYY YYYX XXXX
       |   ||  |     +---- coarse X（tile 列）
       |   ||  +---------- coarse Y（tile 行）
       |   ++------------- 名称表选择
       +------------------ fine Y（tile 内像素行）
x: fine X（3 位）    w: 第一/第二次写锁存
```

- `$2005`/`$2006` 写入的是 t，渲染时在固定时机把 t 复制到 v。
- 渲染时：每 8 点 coarse X 加 1，第 256 点 Y 加 1，第 257 点把 t 的水平部分复制到 v，预渲染行 280-304 点复制垂直部分。

## 4. 一条扫描线上发生了什么

```text
点 0        空闲
点 1-256    每 8 点取一次：名称表字节 → 属性字节 → 图案低位 → 图案高位
            同时输出像素；精灵评估（65-256 点）
点 257-320  取下一行 8 个精灵的图案（A12 会在这里翻转，MMC3 靠它计数）
点 321-336  预取下一行前两个 tile
点 337-340  两次无用的名称表读取
```

背景用两个 16 位移位寄存器（图案）和两个 8 位移位寄存器（属性）实现平滑滚动，fine X 选择移位寄存器的哪一位输出。

## 5. 精灵

- OAM 有 64 个精灵，每个 4 字节：Y、tile、属性（调色板/优先级/翻转）、X。
- 每行最多显示 8 个精灵。评估阶段把命中当前行的精灵复制到 32 字节的次级 OAM。
- **精灵溢出 bug**：找到 8 个精灵后，硬件会错误地同时递增精灵索引 n 和字节索引 m，导致溢出标志误报/漏报。本项目按真实状态机实现。
- **精灵 0 命中**：精灵 0 的不透明像素和背景不透明像素重叠时置位。x=255 不命中；左 8 像素被裁剪时不命中；背景和精灵必须都开启。

## 6. VBlank 与 NMI

- 第 241 行第 1 点置位 VBlank，如果 PPUCTRL bit7 开启则拉低 NMI 线。
- 预渲染行第 1 点清除 VBlank、精灵 0、溢出。
- **竞争**：恰好在 VBlank 置位前 1 点读取 `$2002`，会读到 0 并且吞掉这一帧的 NMI。
- VBlank 期间再打开 NMI 使能，会立即触发 NMI。
- **奇数帧跳点**：渲染开启时，奇数帧的预渲染行少 1 个点（帧长 89341.5 点的来源）。

## 7. 其他硬件细节（已实现）

- 渲染期间访问 `$2007` 会同时递增 coarse X 和 Y（硬件故障）。
- 渲染期间写 `$2004` 只让 OAMADDR 加 4 而不写入。257-320 点 OAMADDR 被清零。
- OAM 第 3 字节 bit2-4 不存在，读回为 0。
- PPU 开放总线（I/O 锁存）约 600ms 逐位衰减；读调色板时高 2 位来自开放总线。
- 渲染关闭且 v 指向调色板时，屏幕显示该颜色（"背景色 hack"）。
- 灰度、RGB 强调位、上电调色板初值。

## 8. 与 Mapper 的交互

PPU 每次访问图案表都会经过卡带（`Mapper.PpuRead`），所以：

- **MMC3** 通过观察地址线 A12 的上升沿计数扫描线（需要过滤背景取图时的抖动，A12 低电平要保持约 3 个 M2 周期）。
- **MMC2/MMC4** 观察读取 `$FD`/`$FE` 图块的地址来切换 CHR 页。
- 非渲染期间 `$2006`/`$2007` 改变地址也会通知卡带（`NotifyPpuAddress`）。
